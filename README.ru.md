# Ayla Resolve

Локальное дополнение к [Pi](https://pi.dev) для DaVinci Resolve Studio: читает проект, показывает агенту текущий кадр и работает с ограниченной, разрешённой частью интерфейса.

[English](README.md) · [Ayla tools](https://github.com/kekma-dot/ayla-tools) · [MIT](LICENSE)

> Экспериментальный пакет, только macOS. Native-рецепты требуют Resolve MCP **21.1.1 и точной проверенной схемы**; на других версиях доступна только диагностика статуса. Фильм он за вас не смонтирует и не покрасит.

## Установка

Нужны macOS, Node **22.19+**, Pi **1.3.0**, Git и установленная лицензированная DaVinci Resolve Studio с `ResolveMCP`.

В терминале, не в чате Pi:

```sh
pi install git:github.com/kekma-dot/ayla-tools-resolve
```

Запустите Pi или выполните `/reload` в уже открытой сессии. Resolve откройте сами, затем введите в Pi:

```text
/resolve status
```

Стандартный путь к native-бинарю:

```text
/Applications/DaVinci Resolve/DaVinci Resolve.app/Contents/Applications/ResolveMCP
```

Если Resolve установлен в другом месте, задайте абсолютный путь при запуске Pi:

```sh
RESOLVE_MCP_PATH="/absolute/path/to/ResolveMCP" pi
```

Установка не запускает Resolve, не меняет проект и не выдаёт разрешения macOS. Для GUI-инструментов нужен «Универсальный доступ», для снимков окна может понадобиться «Запись экрана». API-вызовам не нужно ни то, ни другое.

## Использование

- «Проверь, поддерживается ли моя установка Resolve».
- «Опиши открытый проект и покажи первые 20 видеоклипов дорожки 1».
- «Покажи текущий кадр таймлайна, не двигая playhead».
- «Подготовь копию таймлайна с синими метками на относительных кадрах 0 и 120. Не применяй».

| Инструмент или команда | Что делает |
|---|---|
| `resolve_inspect` | Статус, сводка проекта и таймлайна, ограниченный список клипов дорожки |
| `resolve_preview` | Экспортирует текущий кадр во временный приватный PNG, отправляет его модели и удаляет файл |
| `resolve_control` | Окна и разрешения, снимок одного проверенного окна Resolve, разрешённые меню верхнего уровня, переключение страницы |
| `resolve_plan` | Черновик копии таймлайна с синими метками, до 50 штук, ничего не меняет |
| `/resolve pending` | Показывает запись о незавершённой операции |
| `/resolve apply DIGEST` | Применяет черновик: копирует таймлайн, ставит метки, сохраняет проект |

Кадр метки это целое смещение от начала таймлайна, не таймкод и не абсолютное значение кадра. Черновик живёт десять минут. Применение сохраняет все несохранённые изменения проекта, а копия таймлайна может делить медиа и grades с оригиналом. Перед этим сделайте резервную копию проекта.

`/resolve apply` делает человек. Вы вводите digest и подтверждаете его в интерфейсе Pi; модель не может подтвердить собственный план.

## Ограничения

- Нет исполнения скриптов, кликов, ввода клавиш, нарезки, транскрипции, обработки звука, цветокоррекции, Fusion и рендера. Открытие меню не выполняет его пункты.
- Не двигайте интерфейс и playhead, пока снимается кадр. Достоверность цвета, эффектов и композитинга live-проверками не подтверждена.
- При другой native-версии или схеме рецепты блокируются. Не правьте hash, чтобы пропустить более новую версию.
- Таймаут после отправки означает неизвестный результат. Не повторяйте изменение. Сначала проверьте `/resolve pending` и реальный проект, сохранив запись об операции.
- Linux прогоняет portable unit- и loader-тесты, но этот native backend там не работает. Windows не квалифицирована.
- Тесты используют синтетические native-серверы и проверяют отмену, cleanup, несовпадение схемы, отсутствие повторов, границы GUI и подтверждение человеком. Реальный проект или результат монтажа они не подтверждают.
- Live-статус проверялся на настоящей установке Resolve. Preview и mutation не запускались.

## Приватность

ResolveMCP работает локально как короткоживущий дочерний процесс расширения. Названия проектов и клипов, которые возвращаются в Pi, попадают в диалог модели. Запрошенные кадры и снимки окна уходят текущему провайдеру модели и могут содержать имена файлов и диалоги, поэтому запрашивайте только то, что можно отправлять.

Native stderr в чат не выводится, файлы превью временные. Записи об операциях лежат локально в `${XDG_STATE_HOME:-$HOME/.local/state}/pi-davinci-resolve/` и остаются после удаления пакета. Эти проверки уменьшают риск случайных действий, но не заменяют OS sandbox.

## Удаление и отключение

```sh
pi remove git:github.com/kekma-dot/ayla-tools-resolve
```

Затем выполните `/reload`. Чтобы отключить без удаления, используйте `pi config` или фильтр пакета `"extensions": []`. Не ставьте рядом другое дополнение с теми же `resolve_*` инструментами или командой `/resolve`.

## Разработка

```sh
npm ci --ignore-scripts
PI_TEST_SDK_ROOT="$PWD/node_modules/@earendil-works/pi-coding-agent" npm test
```

Проверенная база хоста это Pi 1.3.0; wildcard peers нужны для host mapping Pi, а не как обещание совместимости. CI прогоняет те же проверки на macOS и Linux, пропуская macOS-only сценарии на Linux. Работа с живым Resolve проверяется вручную.
