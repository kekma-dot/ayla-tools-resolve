# Ayla Resolve

**Внимательный взгляд на ваш таймлайн.** Небольшое локальное дополнение к [Pi](https://pi.dev) для DaVinci Resolve Studio: исследуйте проект, покажите агенту текущий кадр и используйте ограниченную навигацию по интерфейсу.

[English](README.md) · [Ayla tools](https://github.com/kekma-dot/ayla-tools) · [MIT](LICENSE)

> **Экспериментальный пакет, только macOS.** Не автономный видеоредактор. Native-рецепты требуют Resolve MCP **21.1.1 и точного проверенного schema hash**. Для других версий доступна только диагностика статуса. Личный сервер Айлы, профиль и аккаунт автора не нужны.

## Установка в обычный Pi

Нужны Node **22.19+**, Pi **1.3.0**, Git и установленная лицензированная DaVinci Resolve Studio, включающая `ResolveMCP`. Эти программы не входят в пакет.

В обычном терминале, не в чате Pi:

```sh
pi install git:github.com/kekma-dot/ayla-tools-resolve
```

Запустите Pi либо выполните `/reload` в существующей сессии. Самостоятельно откройте Resolve. В Pi введите:

```text
/resolve status
```

Стандартный путь к native-серверу:

```text
/Applications/DaVinci Resolve/DaVinci Resolve.app/Contents/Applications/ResolveMCP
```

Если программа установлена в другом месте, задайте **абсолютный** путь при запуске Pi:

```sh
RESOLVE_MCP_PATH="/absolute/path/to/ResolveMCP" pi
```

Пакет не запускает Resolve автоматически, не меняет проект при установке и не выдаёт разрешения macOS. Для GUI-операций требуется разрешение «Универсальный доступ», для снимков окна может потребоваться «Запись экрана». Выдавайте только нужные разрешения; API-операциям нужны не все GUI-разрешения.

## Что попросить у агента

- «Проверь, поддерживается ли моя версия Resolve».
- «Опиши открытый проект и первые 20 видеоклипов дорожки 1».
- «Покажи текущий кадр, не двигая playhead».
- «Подготовь план копии таймлайна с синими метками на относительных кадрах 0 и 120. Ничего не применяй».

| Инструмент / команда | Возможности |
|---|---|
| `resolve_inspect` | Статус, текущий проект/таймлайн, ограниченный список клипов дорожки |
| `resolve_preview` | Экспорт текущего кадра во временный приватный PNG, передача модели, удаление файла |
| `resolve_control` | Окна/разрешения Resolve, снимок одного проверенного окна, разрешённые меню верхнего уровня, переключение страницы |
| `resolve_plan` | План копии + до 50 синих меток, **без изменения проекта** |
| `/resolve pending` | Чтение записи о незавершённой/неопределённой операции |
| `/resolve apply DIGEST` | **Подтверждение человеком в UI**; копия таймлайна, метки и сохранение текущего проекта |

Кадры меток — целочисленные **смещения от начала таймлайна**, не таймкоды и не абсолютные vendor frame values. План действителен десять минут. Применение сохраняет **все текущие несохранённые изменения проекта**; копии могут разделять медиа и grades. Перед экспериментальным рецептом сохраните резервную копию проекта.

## Намеренные ограничения

Нет произвольных скриптов, кликов, ввода клавиш, нарезки, транскрипции, обработки звука, цветокоррекции, Fusion и рендера видео. Открытие меню не выполняет его пункты. Отдельный полный scripting MCP этот пакет не устанавливает и не настраивает.

- Не двигайте интерфейс/playhead при захвате кадра. Полная достоверность цвета, эффектов и композитинга не подтверждена live-проверками.
- При изменении native-версии или схемы рецепты блокируются. Не подменяйте hash ради совместимости.
- Таймаут после отправки — **неизвестный результат**, а не разрешение повторить операцию. Сначала проверьте `/resolve pending` и реальный проект. Не удаляйте pending-запись автоматически.
- Linux поддерживает portable unit/loader tests, но **не этот native backend**. Windows не квалифицирована.
- Тесты проверяют синтетический native-сервер, отмену, cleanup, schema mismatch, отсутствие повторов, GUI-границы и approval. Это не сертификация любых реальных проектов или результатов монтажа.

## Приватность и безопасность

ResolveMCP работает локально в короткоживущем дочернем процессе пакета. Нет backend Айлы и отдельной телеметрии. Названия проектов/клипов попадают в диалог модели Pi. Запрошенные кадры и снимки окна передаются **текущему провайдеру модели**; на снимках могут быть имена файлов и диалоги. Не запрашивайте материалы, которые нельзя отправлять провайдеру.

Native stderr не выводится в чат. Кадры хранятся временно. Приватные локальные квитанции операций находятся в `${XDG_STATE_HOME:-$HOME/.local/state}/pi-davinci-resolve/`; удаление пакета не стирает их, проекты или медиа. Проверки уменьшают риск случайных действий, но не являются OS sandbox.

## Удаление и отключение

```sh
pi remove git:github.com/kekma-dot/ayla-tools-resolve
```

После этого выполните `/reload`. Для временного отключения используйте `pi config` или фильтр пакета `"extensions": []`. Не устанавливайте одновременно другое дополнение с теми же `resolve_*` tools или командой `/resolve`.

## Разработка и проверка

```sh
npm ci --ignore-scripts
PI_TEST_SDK_ROOT="$PWD/node_modules/@earendil-works/pi-coding-agent" npm test
```

Проверяемая базовая версия — Pi 1.3.0. Wildcard peers нужны для Pi host mapping и не гарантируют работу на будущих версиях. CI запускает проверки на macOS и Linux; macOS-only сценарии явно пропускаются на Linux. Live Resolve проверяется отдельно вручную, а не выдаётся за результат CI.
